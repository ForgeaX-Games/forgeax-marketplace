# Task 3 — host-context business service

Base commit: `c86da011e158e66747a3c0bad58bfa600ae0ca5f`.
Required host bootstrap refresh: `1f5be35` (reviewed host commit `e99d2eff`).

## Delivered

- Added one `createWbGameVideoService(context)` surface for graph, asset,
  character/scene intake, shot script, keyframe, video, and node-video flows.
- Added one transport-neutral `createWbGameVideoRouter(context)` implementing
  every Task 3 route with raw byte requests/responses and normalized errors.
- Moved game-owned reads/writes to bounded `context.files`; character discovery
  uses the reviewed `files.list("characters")` capability and scene discovery
  uses bounded `textures/index.json`.
- Moved reference and generated bytes through `context.media`, while model
  calls use `context.models`. Model-owned URLs and game/package paths never
  become public fields; playable locators come only from the host media
  capability.
- Added extension-owned bundled-media lookup using immutable module-relative
  paths. Range reads are positional, so `bytes=0-3` reads and returns exactly
  four bytes rather than buffering an entire MP4.
- Serialized capability-backed manifest mutations to prevent concurrent
  generation/import requests from losing records.
- Preserved the legacy tool handler bridge for Task 4; no Arrival/ForgeaX
  context migration was performed in this task.

## Review follow-up

An independent review initially blocked submission on unbounded paid generation
work and flagged host-media portability, concurrent manifest loss, full-file
Range buffering, and authoritative-blueprint handling. The final implementation
adds method-specific closed input contracts and 60/120-second caps, preserves
validated host media locators without Kino assumptions, serializes manifest
writes, performs positional Range reads, and keeps a valid blueprint readable
when `project.json` metadata is corrupt. Regression tests cover each behavior.

A second review hardened those boundaries further:

- Manifest mutation queues now use the stable host game root, so fresh context
  and file-capability wrappers for the same game still serialize. A rejected
  mutation cannot poison subsequent work.
- Keyframe and video assets are visible as `generating` before the model settles,
  then retain the same registry id through `ready` or `failed`. Multi-segment
  node generation preserves completed segments when a later segment fails.
- Public records are field-whitelisted and deeply sanitized. Absolute paths,
  file URLs, model/provider URLs, provider mappings, and sensitive legacy nested
  metadata never cross the service boundary. A claimed locator survives only
  when its game-scoped asset id and exact URL are independently attested by the
  Workbench media capability; optional media metadata is not required.
- Model references never use a manifest `provider.ref` directly. The referenced
  id must first exist in the host media capability for the bound game, so a
  forged foreign id fails before any model call.
- Every tool-shaped service input is compiled directly from the published
  Draft 2020-12 JSON schema with Ajv. Router query keys are closed and
  single-valued, and invalid generation input is rejected before a model call.
- Multi-segment node generation returns completed records plus the stable failed
  record in segment order, so callers do not lose resumable ids.
- Router error envelopes—including invalid byte ranges—consistently include
  `target` and `retryable`.
- `getAsset(assetId)` retains its required string business-service interface.
  The exported `getAssetIdFromArgs()` adapter owns published object-schema and
  host-bound `gameSlug` validation for Task 4 tool and router callers.

Fresh follow-up verification: `bun test server/host` passed **90 tests with
0 failures**; `bun run lint` passed; and direct ESM plus declaration builds of
the service and router passed.
